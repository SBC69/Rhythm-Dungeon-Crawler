## 1. Принятые правила

Уже принято пользователем:

1. В режиме на время сначала открыто только первое подземелье. Каждая победа над финальным боссом100 открывает следующее по порядку. Предыдущие открытия сохраняются после смерти/выхода.
2. Экипированные оружие, броня и амулет могут переноситься после победы. При смерти или выходе у костра экипировка сбрасывается. Рука/сундук, временные усиления, HP и штраф этажа между походами не переносятся.
3. Общий кошелёк, три исхода, золото при смерти/выходе и дополнительная999 за финального босса сохраняют принятые правила. Полное закрытие незавершённого timed откатывает весь игровой прогресс к снимку перед входом, включая переносимую экипировку.
4. С ростом подземелий должны усиливаться враги и награды. Все коэффициенты, пять тем, новые стартовые параметры и распределение комнат ниже утверждены.
5. Последующим ответом пользователь принял три пункта: со второго этажа6обычных+1элитный+2ловушки+босс; максимум20сырого урона ловушки; после потери экипировки базовый комплект уровня выбранного подземелья. Эти принципы повторного принятия не требуют. Затем пользователь утвердил весь оставшийся пакет: составF1, коэффициенты роста/стартовых параметров, скорость ростаDC и пять тем. Экономическая балансировка цен отдельно поручена и выполнена в [отчёте v2](<C:/Users/sapav/VS Code Projects/game002/design/balance/economy-balance-v2-2026-10-20.md>).

Пропуск закрытого подземелья невозможен. Повторная победа не открывает два следующих подземелья; следующий ID берётся из каталога, а не вычисляется из числа callback. Для последнего определённого подземелья `next_dungeon_id=null`: успех возвращает в деревню, не создаёт несуществующий контент.

## 3. Одна шкала глубины

Для timed:

```text
D = порядковый номер подземелья, D >= 1
F = этаж текущего подземелья, 1 <= F <= 100
R = комната, 1 <= R <= 10
Q = 100 * (D - 1) + (F - 1)       # сквозная глубина от 0
Q_entry = 100 * (D - 1)
T = floor((R - 1) / 3)            # 0, 1 или 2 для обычных комнат
V = -1 / 0 / +1                  # фиксированный сдвиг архетипа 01/02/03
```

Второе подземелье начинается сQ100, не сQ0. Перенесённая экипировка сохраняет фактические параметры и заточку: её не усиливают повторно при входе и не пересчитывают по новомуQ. Новая добыча рассчитывается поQ в момент создания экземпляра.

Endless использует те же коэффициенты сQ=F−1. Темы сменяются каждые100этажей только среди открытых в timed: при входе сохранить упорядоченный список unlocked timed IDs, index=floor((F−1)/100) mod pool.size. При двух открытых темах F1–100 crypts,101–200 ash_forges,201–300 crypts. Числовая глубина Q, HP/инвентарь и прогресс не сбрасываются. На F100/200… обычный босс этажа, без final success/999/unlock. В endless мягкий состав7/2 относится только к F1 похода; смена темы не запускает новый поход/первый этаж.

## 4. Мощь врагов, предметов и расходников

| Значение | Утверждённая формула |
|---|---|
| Обычный враг | M = 4 + 2Q + T + V |
| Элитный враг | M = 6 + 3Q + min(8, floor(Q/20)) + T + V |
| Босс обычного этажа | M = 9 + 3Q + min(12, floor(Q/10)) |
| Финальный босс100 | M = 35 + 3Q |
| Новое оружие/броня | power = base_power_definition + Q |
| Новый свиток, включая алхимика | power_buff = base_buff_definition + Q |
| Новое зелье, включая алхимика | heal = base_heal_definition + 5Q, фактическое лечение до max_hp |

Архетипы обычных/элитных врагов выбираются с весами45%/35%/20% дляV−1/0/+1. Дополнительного случайного ±1 поверхV нет: размах угрозы заранее ограничен. Боссы01/02 чередуются на нечётных/чётных этажах1–99 и используют одну формулу; отличия — тема и представление. Финальный босс — отдельный шаблон.

Базовые характеристики героя не растут: max_hp50, base_power2. Урон боя и принятого провала побега остаётся прежним: при M>P сырой урон10×(M−P), затем броня и минимум1. При P≥M урон0. Цены и предел заточки не меняются; +2/+3/+4/+5 берутся из согласованной стадии кузницы, максимум5 на предмет.

### Восстановление после потери экипировки

**Стартовые коэффициенты утверждены:** базовое оружие/броню при старте создавать сpower=2+Q_entry, заточка0. Два обычных стартовых зелья и два обычных свитка создаются по тому жеQ_entry. Стартовый амулет сохраняет обычный бонус+2 к кубикам, без роста. Для endless Q_entry=0; смена темы не выдаёт новый набор.

Так смерть сбрасывает заработанную экипировку, редкость и заточку, но уже открытое подземелье остаётся доступным без обязательного повторного прохождения всей ранней цепочки. Это стандартные стартовые ID, не новые карты алхимика и не бесплатное восстановление старой заточки. Сохранённый после победы комплект можно выбрать вместо базового; выбор выполняется до начала таймера и фиксируется во входном снимке. Параметры перенесённых предметов при этом не пересчитываются.

Проверка входа во второе подземелье: базовый комплект даётP206, стартовый свиток+103; босс1 имеетM319. Два стартовых свитка позволяют достичьP412. Перенесённые редкие предметы сэтажа99 первого подземелья и пятью заточками по+2 даютP222; один стартовый свиток даётP325, достаточно дляM319. Здесь берётся экипировка сF99: loot этажа100 до финального босса ещё находится в сундуке и не считается заранее экипированным. Перенос сохраняет преимущество, потеря предметов не требует вернуть удалённый комплект.

## 7. Ловушки при неизменных50HP

Предел20сырого урона утверждён пользователем. Формулы медленного прироста урона/DC и делители25/40 утверждены:

```text
DC = min(10, base_dc + floor(Q/40))
raw_full_damage = min(20, base_trap_damage + floor(Q/25))
raw_partial_damage = max(1, floor(raw_full_damage/2))
actual_damage = max(1, raw_damage - armor_reduction)
```

Успех и любой дубль дают0урона, минимум1 применяется только к реально повреждающему исходу. Прежние base_dc5/6/7 и base_damage10/12/8 остаются.
