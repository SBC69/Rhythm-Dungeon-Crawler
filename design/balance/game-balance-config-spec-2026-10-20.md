Технические размеры интерфейса и длительности анимаций не относятся к балансным настройкам. Числа в формулах GDD и тестовых ожидаемых результатах документируют настройки; runtime читает JSON.

## Контракт формул

Обозначения: b — объект конфигурации; F/R/D начинаются с1; Q начинается с0; U — уже выполненные заточки.

```text
Q_timed = b.modes.timed.depth_stride * (D-1) + (F-1)
Q_endless = F-1
Q_entry_timed = b.modes.timed.depth_stride * (D-1)
room_bonus = floor((R-1) / enemy.room_bonus_divisor)
regular = regular.base + regular.depth_multiplier*Q + room_bonus + archetype.power_offset
elite = elite.base + elite.depth_multiplier*Q + min(elite.depth_extra_cap, floor(Q/elite.depth_extra_divisor)) + room_bonus + archetype.power_offset
floor_boss = floor_boss.base + floor_boss.depth_multiplier*Q + min(floor_boss.depth_extra_cap, floor(Q/floor_boss.depth_extra_divisor))
final_boss = final_boss.base + final_boss.depth_multiplier*Q
new_gear = card.power + items.power_per_depth*Q
new_buff = card.power_buff + items.buff_per_depth*Q
new_heal = card.heal + items.healing_per_depth*Q
upgrade_price = upgrades.price_base + upgrades.price_step*U
upgrade_gain = upgrades.power_gain_by_forge_stage[forge_stage]
G = economy.gold_per_victory.base + floor(Q/economy.gold_per_victory.depth_divisor)
trap_DC = min(traps.dc_cap, template.base_dc + floor(Q/traps.dc_depth_divisor))
trap_raw = min(traps.raw_damage_cap, template.base_damage + floor(Q/traps.damage_depth_divisor))
trap_partial = max(combat.minimum_damaging_hit, floor(trap_raw/traps.partial_damage_divisor))
escape_DC = clamp(escape.dc_base + max(0,monster_power-hero_power), escape.dc_min, escape.dc_max)
```

В бою при достаточной мощи урон0, иначе разница×combat.damage_per_power_gap, затем броня и combat.minimum_damaging_hit. Побег использует тот же штраф по разнице при принятом провале. Ловушка: сначала дубль/успех; частичный успех при sum≥DC−partial_success_margin; полный провал иначе. Броня и минимум только для повреждающих исходов. Эффект алтаря — только полный провал; эффективная base_power=max(hero.minimum_effective_base_power, base_power−floor_penalty), на новом этаже penalty0. Новые экземпляры масштабируются один раз, перенесённые не пересчитываются.

Формула смерти при C>S: S+ceil((C−S)*numerator/denominator); при C≤S сохраняется C. Прямые4G первой победы уже входят в C,999 добавляется один раз terminal-транзакцией. Повтор final не существует, не выдаёт монеты/карту; после девятой комнаты последнего этажа success, итог C. Веса нормализуются по сумме положительных весов; выбор без возвращения. Количества8наград за этаж, 11G/12G и полная цена заточки500 вычисляются из конфигурации, не являются отдельными настройками.

## Валидация и совместимость

1. Проверять schema_version и все обязательные ключи/типы/допустимые enum. Запретить NaN/Infinity, отрицательные HP/золото/цены/количества и нецелые значения там, где требуются целые. Нулевые награды/бонусы и отключённые веса допустимы; положительная сумма весов обязательна. Все делители положительны, numerator/denominator задают долю0…1, dc_min≤dc_max. Ошибка содержит путь к полю.
2. Проверять состав каждой цепочки: сумма regular+elite+trap=rooms_before_boss; boss_room=rooms_before_boss+1; диапазон элиты лежит в обычных комнатах и вмещает элит; starter ID существует/правильного типа; pool доступных положительных весов вмещает offer_count, pick_count≤offer_count. Алгоритм дубля требует две кости; это ограничение формулы, не возможность произвольно сменить dice.count. Некорректное изменение отвергается.
3. Проверять последовательность подземелий/next без циклов и неизвестных ID; stage_prices/кузница/стадии алхимика согласованы; prerequisites существуют и не создают недостижимого цикла. Предыдущая стадия здания всегда обязательна. Параметры старта/формулы должны оставлять все вычисления в допустимом диапазоне Godot int; переполнение не обрезается молча. Не каждый допустимый JSON гарантирует проходимость.
4. Новый поход получает immutable снимок полного баланса, balance_version и SHA-256 файла. Сохранение содержит снимок, его hash проверяется по сохранённым исходным байтам либо канонической сериализации. Активный endless продолжает прежний снимок после обновления файла; новые походы используют новый. Предметы сохраняют фактические значения, финальные боссы остаются погибшими. Старые схемы мигрируют явно. Не применять новые настройки к живому run молча.
5. Loader не выполняет произвольные выражения из JSON: формулы реализованы в чистом коде с перечисленными параметрами. Новая форма формулы — изменение кода/схемы, а настройка имеющегося коэффициента — правка этого файла. UI, domain и экономический анализ не содержат запасных балансных литералов. Запись/проверки конфигурации выполняются до запуска нового run, ошибки не меняют текущий профиль.

Политики симуляции (запас500монет, частота смены оружия, число trials/seed) остаются в модели: это поведение исследуемого игрока и настройки эксперимента, а не правила игры. Модель обязана брать из JSON цены/награды/эффекты/веса/старт/пределы и записывать version/hash. Вручную менять результаты JSON нельзя: только повторный запуск модели.
